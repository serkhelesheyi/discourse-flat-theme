# ۶. برنامهٔ اجرای آزمون زنده — فاز ۶ (نسخهٔ ۱، ۲۰۲۶-۱۰-۲۲)

> **کاربری این سند:** بندهای باقی‌ماندهٔ فاز ۶ نقشهٔ راه (`docs/02-roadmap.fa.md`) فقط با یک نمونهٔ Discourse واقعی قابل انجام‌اند. این سند دستورکار دقیق همان جلسه است: از راه‌اندازی محیط تا ثبت نتیجه، اسکرین‌شات و بستن فاز.
>
> **قاعده:** هر نتیجهٔ «قبول/رد» باید با تاریخ، مرورگر، عرض دید و حالت ثبت شود. هیچ موردی بدون مشاهده «قبول» علامت نمی‌خورد. اگر موردی رد شد، به‌جای اصلاح فوری، یک ردیف در بخش ۹ ثبت و به فاز مربوطه برگردانده می‌شود.

## ۱) پیش‌نیازها

| مورد | مقدار لازم | یادداشت |
|---|---|---|
| Discourse | `2026.6.0` یا بالاتر (همان `minimum_discourse_version`) | نسخه را در `/admin/upgrade` یا `/site.json` ببینید |
| دسترسی | ادمین یا Theme creator | برای ساخت/پیش‌نمایش تم |
| Ruby + gem | `gem install discourse_theme` | CLI رسمی؛ نسخه را با `discourse_theme --version` ببینید |
| Node / pnpm | Node ≥22، pnpm 10 | فقط برای `pnpm lint` پیش از هر آپلود |
| مرورگر | Chrome یا Firefox به‌روز + DevTools | برای شبیه‌سازی موبایل، `prefers-reduced-motion` و کنتراست |
| افزونه‌ها (اختیاری ولی برای پوشش کامل لازم) | `discourse-post-event`، `discourse-gamification`، `whos-online` | بدون این‌ها بخش‌های مربوطهٔ rail طبق طراحی مخفی می‌مانند و «خطا» نیست |

**هرگز** کلید API یا فایل `~/.discourse_theme` را کامیت نکنید. مخزن فقط `.env` و `.discourse-site` و سکرت‌ها را ignore می‌کند، ولی محل درست اعتبارنامه فقط `~/.discourse_theme` است.

## ۲) راه‌اندازی محیط و آپلود تم

```bash
pnpm install --frozen-lockfile
pnpm lint                     # باید سبز باشد؛ تم ناسالم آپلود نکنید
gem install discourse_theme   # یک‌بار
discourse_theme watch .       # از ریشهٔ همین ریپو
```

در اولین اجرا CLI آدرس سایت و API key را می‌پرسد و در `~/.discourse_theme` (YAML، per-directory) ذخیره می‌کند. سپس بین «تم موجود» و «ساخت تم جدید» انتخاب می‌دهید:

- **ساخت تم جدید:** برای یک سایت آزمایشی، گزینهٔ «Create and sync with a new theme».
- **تم موجود:** اگر تم را قبلاً از گیت نصب کرده‌اید، همان را انتخاب کنید تا `theme_id` ثبت شود.

پس از آپلود، CLI سه آدرس چاپ می‌کند؛ این‌ها را در برگهٔ آزمون بریزید:

| خروجی | کاربرد |
|---|---|
| `…/?preview_theme_id=ID` | پیش‌نمایش تم بدون تغییر تم پیش‌فرض سایت |
| `…/admin/customize/themes/ID` (یا `/my/themes`) | تنظیمات تم |
| `…/theme-qunit?id=ID` | تست‌های QUnit تم (در این ریپو تست JS نداریم؛ فقط برای اطمینان از نبود خطای بارگذاری) |

**مهم:** آزمون را روی یک سایت آزمایشی یا با `preview_theme_id` انجام دهید، نه با تغییر تم پیش‌فرض یک سایت Production. برای بررسی رفتار «تم پیش‌فرض» (مثل `--default-interface`) یک مرحلهٔ جدا در بخش ۶ لازم است.

اگر تم را تغییر دادید و `watch` قطع شد، فقط دوباره `discourse_theme watch .` بزنید؛ نیازی به حذف `~/.discourse_theme` نیست.

## ۳) دادهٔ آزمایشی لازم (تا بخش‌های تم واقعاً رندر شوند)

قبل از آزمون این‌ها را در سایت آزمایشی بسازید؛ در غیر این صورت «بخش دیده نشد» را نمی‌توان به تم نسبت داد:

1. **حداقل ۲ دستهٔ رنگی** با رنگ badge متفاوت + یک زیردسته (برای `--row-cat` و topic list).
2. **۸–۱۰ موضوع** با برچسب، یک موضوع pin شده، یک موضوع بسته، یک موضوع با excerpt بلند (برای `show_topic_excerpts`).
3. **حداقل یک موضوع طولانی** با: نقل‌قول تودرتو (۲ سطح)، جدول، بلوک کد، لیست، تصویر onebox، poll، و اگر افزونه هست پاسخ حل‌شده.
4. **کاربر آزمایشی** با: avatar، بنر پروفایل (برای `has-background`)، bio، location/website، ۲ گروه، آمار فعالیت. یک کاربر هم **بدون** بنر بسازید (برای مسیر `no-background`).
5. **Gamification:** یک leaderboard با `id = 1` (یا `rail_leaderboard_id` تم را با همان id تنظیم کنید) و چند امتیاز.
6. **Post event:** حداقل ۳ رویداد در ۳۰ روز آینده (برای بخش «رویدادهای پیش‌رو»).
7. **whos-online:** اگر افزونه فعال است، چند کاربر آنلاین (می‌توانید با چند تب/مرورگر شبیه‌سازی کنید).
8. **برچسب‌های پرکاربرد:** چند برچسب با استفادهٔ تکراری (برای بخش «برچسب‌های محبوب»).
9. **گفتگو/چت:** یک پیام مستقیم برای بررسی دکمه‌های موبایل پروفایل (در صورت نصب افزونهٔ chat).

## ۷) چک‌لیست مخصوص فارسی/RTL

در حالت `fa_IR` (ماتریس ۵–۸):

1. `<html dir="rtl">` باشد و تم هیچ `direction` سراسری اضافه نکرده باشد (DevTools → Computed روی `body`).
2. hero: جستجو، عنوان و زیرعنوان وسط‌چین و بدون پرش؛ آیکن ذره‌بین سمت راست.
3. rail: پیکان «مشاهدهٔ همه» و پیکان لینک‌های سریع آینه شده؛ در hover جهت حرکت طبیعی باشد.
4. اعداد rel: رویدادها (ماه/روز) و شمارندهٔ آنلاین با **ارقام فارسی**؛ نام ماه رویدادها فارسی و **بدون** پسوند «ماه» («اکتبر» نه «۱۰ ماه»).
5. `letter-spacing`: در همهٔ تیترها/برچسب‌ها/هدر بخش‌های sidebar صفر باشد (حروف فارسی به هم نچسبند/جدا نشوند).
6. بدنهٔ پست فارسی: line-height بازتر از LTR، تیترهای داخل پست بدون تداخل اعراب.
7. تایم‌لاین موضوع در سمت چپ (آینه)، بدون سرریز.
8. فرم ورود/ثبت‌نام، OTP و دکمه‌های کامپوزر آینه و قابل استفاده باشند.
9. هیچ اسکرول افقی در ۳۹۰px وجود نداشته باشد (`document.documentElement.scrollWidth <= innerWidth`).
10. شخصیت‌های ترکیبی (فارسی + لاتین + عدد) در عنوان موضوع و نام کاربری درست بچینند.

- پنجرهٔ تمام‌صفحه با عرض ۲۵۶۰ (DevTools بسته)، بدون نوار آدرس.

- حجم را با WebP یا `cwebp -q 80` پایین بیاورید؛ متادیتا را حذف کنید.
- پس از افزودن، تم را دوباره آپلود کنید و در `/admin/customize/themes/ID` پیش‌نمایش تصویر را ببینید.

### ۹-۱) نتایج تأییدشده تا ۳٫۱٫۵ (گزارش مالک)

مالک پروژه فروم را روی محیط واقعی خودش آزموده و ایرادها را گزارش کرده است. این جدول **جایگزین ماتریس ۸ حالته نیست** (locale، عرض دید و حالت رنگ در گزارش‌ها ثبت نشده)، ولی نتیجهٔ اصلاح‌ها را مستند می‌کند:

| # | ایراد | نسخهٔ اصلاح | نوع شاهد | نتیجه |
|---|---|---|---|---|
| ۱ | کامپوزر موبایل روی عنوان می‌افتاد / شفاف بود | ۳٫۱٫۱ + ۳٫۱٫۲ | گزارش مالک (متن) | ✅ تأیید صریح: «مشکل composer موبایل حل شد» |

| ۳ | برگهٔ فیلتر «آخرین» فلش می‌زد | ۳٫۱٫۵ | گزارش مالک + اسکرین‌شات | ✅ تأیید صریح: «مشکل منوی مذکور برطرف شد» |

**آنچه هنوز تأیید نشده و باید در جلسهٔ بعدی ماتریس دیده شود:** حالت روشن/تاریک در دسکتاپ ≥۱۴۴۰px، `fa_IR` در عرض ۳۹۰px به‌طور کامل، صفحهٔ موضوع با نقل‌قول تودرتو و جدول، پروفایل بدون بنر، گروه‌ها، ورود/OTP، `/search` در RTL، `prefers-reduced-motion`، پیمایش کامل با Tab، و هر سه تنظیم `accent_color`/`ui_radius`/`content_max_width` در UI.

## ۱۰) تأیید CI و بستن فاز

```bash
pnpm lint          # سبز
git status         # هیچ فایل اعتبارنامه/اسکرین‌شات خصوصی staged نباشد
```

سپس تغییرات را روی شاخه بفرستید و در GitHub وضعیت workflow `Discourse Theme` (`.github/workflows/discourse-theme.yml`، reuse الگوی رسمی Discourse) را ببینید. CI فقط وقتی «سبز» ثبت می‌شود که اجرای همان کامیت روی GitHub کامل شده باشد؛ اجرای محلی `pnpm lint` جای آن را نمی‌گیرد.

**شرط پایان فاز ۶:**

1. هر ۸ سلول ماتریس (بخش ۴) با دست‌کم یک صفحهٔ نماینده «قبول» شده باشد.
2. چک‌لیست‌های بخش ۵ تا ۷ بدون ایراد باز یا با ایراد مستندشده باشند.
3. `screenshots/light.webp` و `dark.webp` ساخته و کلید `screenshots` در `about.json` اضافه شده باشد.
4. CI روی GitHub سبز باشد.
5. جدول وضعیت `docs/02-roadmap.fa.md` و یادداشت جلسه به‌روز شده باشد (فاز ۳/۴/۶ → ✅).
6. `theme_version` نهایی (اکنون `3.2.0`) و `CHANGELOG.md` با نتیجهٔ آزمون هم‌خوان باشد؛ تغییر رفتار ← `3.2.0`، اصلاح ایراد ← `3.1.6` و بالاتر.
